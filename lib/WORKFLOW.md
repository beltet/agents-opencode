# Flexible project workflow

1. At project start, inspect `AGENTS.md`, `PROJECT_POLICY.md`, installed roles and the current project status.
2. The orchestrator, architect and documenter participate only if installed; otherwise make no assumptions about these roles. Choose experts after an actual skill analysis.
3. Before changing code, identify the task, files, success criteria and compact resource budget. Use the project-approved programming language.
4. Collaborate directly when useful, use bounded tests, and request more expertise instead of bluffing. Avoid duplicating expensive investigations.
5. Work in local task branches as appropriate; coordinate integration and document meaningful changes.
6. Remote Git actions, internet use, external directory access and network shares must follow the project permissions. The presence of a `git remote` does not itself authorize push.
7. For a checkpoint: summarize completed work, current Git state, tests, unresolved risks and next tasks; record meaningful points in project documentation.
8. Do not assume a previously interrupted external command or agent task can automatically resume. Read the checkpoint and inspect the worktree before continuing.

## Handoff template
Task / Goal; Verified facts; Assumptions and unknowns; Work attempted; Paths/tests; Assistance needed; Remaining time and permission boundaries.
